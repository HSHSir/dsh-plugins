# A6 换商家 · dsh-a6-failover 0.8.2

插件监测 DSH 中受管的 A6API 请求，默认匹配名称以 `a6api` 开头的 provider。启动时采用平台默认路由，沿用你在平台设置的选路偏好。健康请求直接发送给平台。

## 安装与接入

1. 准备已启动过的 DSH profile，使用 Node.js 18.17 或以上版本。在本版源码或发布包的根目录运行 `node scripts/install.mjs --profile desktop`。CLI Web 用户将 `desktop` 换为 `web`。自定义 DSH 数据目录时，先设置 `DSH_HOME`。
2. 完全退出 DSH（包括托盘进程），再重新打开。在 DSH 中配置 A6API provider、模型和模型 API 密钥。
3. 打开设置中的「A6 换商家」，核对版本、启用状态、provider 匹配规则和控制面站点，填写该站点的系统访问令牌和用户 ID 后保存。默认控制面为 `https://a6api.vip`。模型 API 密钥用于模型调用，系统访问令牌用于查询与切换商家。

设置页覆盖值保存在 DSH 数据目录的 `a6-failover/config.json`。点击「清除本地覆盖」可恢复 profile 配置。使用脚本安装后，可从解压目录运行 `node scripts/install.mjs --profile desktop --uninstall` 卸载。市场用户可通过 [市场索引](./market/index.json) 核对已发布的版本，再在「插件 → 发现」中安装对应版本。

## 路由策略

| 状态 | 请求行为 |
|---|---|
| 平台默认策略 | 平台选商，插件监测各个请求。从发送到收到首块有效响应计时。 |
| 智能路由（故障接管） | 可恢复的快速故障先按预算原路重试。任一受管请求持续失败，或连续 30 秒没有首块有效响应，就尝试切换到合格商家。 |
| 智能路由（手动） | 点击「开启手动智能路由」，对本次 DSH 运行的所有受管会话生效，持续到点击「恢复平台默认策略」或重启。 |
| 待恢复平台默认 | 自动接管在所有受管请求、重试和切换均空闲后恢复平台路由。上一次运行遗留的插件固定也需要核对并清理。平台确认后才显示已恢复。 |

各会话独立计时。同站点、令牌和模型共用固定商家，并发故障共享切换结果。等待首块的时间**按每次尝试分别计算，互不共享**：原商家加上它自己的同路重试共用一笔 `firstResponseTimeoutMs`（默认 30 秒，到点开始换商）；每换到一家新商家重新计一笔 `firstResponseBudgetMs`（默认 180 秒，给 60 就是每家新商家最多等 60 秒）。换商次数由 `maxSwitchesPerCall` 控制，不再有整轮共用的一次性总预算。向站点确认固定商家的往返耗时单独计 `controlTimeoutMs`，不吃这两笔预算，超时只表示这次不换商，不会让请求失败。收到正文、推理或工具输出后再出错，会保留已输出内容并报告异常，避免重复执行工具。收到有效首块后，连续等待上游 30 秒仍无有效进展时结束该流。自动接管在全部会话空闲一秒后释放；这期间的新请求继续沿用当前商家。启动和手动恢复平台默认时，清除受管令牌下全部模型的固定商家，包括遗留绑定；其他令牌保留。失败时显示正在恢复并后台重试，受影响请求等待确认。手动开启智能路由时不预先绑定，模型收到新请求时才选择并固定商家。

对于明确要求生成文档或文件的简短请求，若回合结束时只有一段准备工作说明且没有工具调用，设置页的最近事件会显示「交付待核对」和核对编号。该提醒供人工复核，DSH 的回合完成状态由宿主维护。

## 智能选商

插件先检查报价、状态和质量门槛。`maxEffectiveRatio` 默认是 `0.7`，即按相同用量假设比较时，商家预计成本最多为官网的 70%。在合格商家中按站点实测延迟从低到高取较快的一半入选，再按预计成本、缓存收益、可靠性和站点延迟加权排序。权重为「价格 / 缓存收益 / 可靠性 / 延迟」四项，可在设置页调整。**P50 只用于「取较快的一半」这个入选门槛，不计入得分**；打分用的是站点的 `last_test_response_ms`（没有实测值时才回退到 P50），延迟越低排越前。单次请求的 30 秒切换阈值使用该请求从实际发送到有效首块的等待时间。

### 上下文窗口下限

`minContextWindowTokens` 默认 `0`（不过滤）。设成 `300000` 就是不考虑明显放不下长上下文的商家。这里有个必须知道的前提：**站点接口并不返回每个商家的模型上下文窗口**——`/api/marketplace/channels` 的 listing 字段里没有任何 context / window / max_tokens 之类字段，`/api/pricing` 的 `long_context_pricing.threshold` 是长上下文档位的**计费**阈值，也不是窗口上限，按 `&capabilities=context_large` 之类参数请求也不会被服务端筛选。所以判定只能建立在有证据的两种来源上：

| 来源 | 怎么来 | 可信度 |
|---|---|---|
| 商家自述（`declared`） | 解析 `description` 等文本里的「1M上下文」「500k context」「25万上下文」「上下文 128K」 | 中，是商家自己写的 |
| 实测（`measured`） | 上游报错里直说 `maximum context length is N` 时记下来，保留 7 天 | 高 |

两者都有时取较小的那个。**没有任何证据的商家一律保留**——宁可保留一家可能偏小的，也不要把没有证据的商家当骗子淘汰掉。设置页商家表的「上下文」列会标出是声明值还是实测值，没有证据显示「未知」。

真实成本按 `G = B×D + (1-B)×E + C×F` 计算：`B` 是缓存命中率、`C` 是输出/输入比、`D/E/F` 分别是缓存读、输入、输出单价。输出 token 独立于输入，不从输入里扣。官网价默认按真实账单校准，可填 `officialPriceOverride` 覆盖站点返回的偏低报价。

官网缓存命中率估算默认 98%（高峰可用 90%）。商家缓存命中率估算优先使用达到 `cacheMeasureMinSamples` 门槛的本机数据，未实测时按 `unmeasuredMerchantCacheHitRate` 估算。输出与输入 token 比例优先采用满足 `outputRatioMinSamples` 的样本，否则采用 `outputToInputRatio`。

## 连接方式与报价缓存

A6API 的域名解析到私有地址段，Node 直连可能超时，而浏览器能打开是因为走了系统代理。插件的连接方式（`connectionMode`）默认 **直连优先**：

| 模式 | 行为 |
|---|---|
| `direct-first`（默认） | 先直连，`directProbeMs`（默认 1500 毫秒）内连不上才切代理；连得上就一直用直连 |
| `proxy-first` | 先代理，失败再试直连 |
| `direct-only` / `proxy-only` | 只用一种 |

代理地址填 `proxyUrl`（留空时依次读环境变量 `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`）。站点真的返回 4xx/5xx 不算「连不上」，不会误切代理。

商家表改由 `channels/search` 按模型拉取（实测单模型 571KB / 0.4s，旧接口是全站 15MB / 7.6s；失败自动回退旧接口）。切换**只读本地缓存**（毫秒级），后台按 `channelsRefreshMs`（默认 60 分钟）只刷 DSH 实际用过的模型；缓存还没准备好时本轮先走平台默认路由，不阻塞请求。下载超时 `channelsTimeoutMs` 默认 30 秒。汇率取报价里的站点实时值，不再手填。

## 设置页与人工举报

打开「A6 换商家 → 当前路由策略」可查看本次运行的策略以及各 provider、模型的实际状态。展开一条路由可读到已确认的商家与渠道、每百万输入 token 的预计成本、缓存命中率及其来源、候选延迟 P50。平台自主选商或样本不足时，相应字段可能为空。设置页定期刷新，也可点击「刷新状态」。

插件在本地记录能从响应流验证的格式异常。设置页从最近 512 条日志中保留最多 20 条格式异常供复核。展开记录后可复制本地请求标识、时间、渠道、判定规则与耗时等脱敏字段，自行核对并决定是否向平台举报。请求标识由插件生成；平台排查时可同时提供时间、模型与渠道。任务未完成、回复不合预期和协议格式异常需要分别判断，单条记录不足以认定商家欺诈。

数据目录默认是用户主目录下的 `.dsh`，自定义时使用 `DSH_HOME`。PowerShell 可查看最近 30 条本地事件。

```powershell
$dshDir = if ($env:DSH_HOME) { $env:DSH_HOME } else { Join-Path $env:USERPROFILE '.dsh' }
Get-Content (Join-Path $dshDir 'a6-failover/events.jsonl') -Tail 30
```

`boot` 事件的 `version` 应为 `0.8.2`。在源码目录运行 `node scripts/self-test.mjs` 可执行本地自检。
