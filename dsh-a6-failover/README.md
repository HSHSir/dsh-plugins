# A6 换商家 · dsh-a6-failover 0.6.2

插件监测 DSH 中受管的 A6API 请求，默认匹配名称以 `a6api` 开头的 provider。启动时采用平台默认路由，沿用你在平台设置的选路偏好。健康请求直接发送给平台。

## 安装与接入

1. 准备已启动过的 DSH profile，使用 Node.js 18.17 或以上版本。在本版源码或发布包的根目录运行 `node scripts/install.mjs --profile desktop`。CLI Web 用户将 `desktop` 换为 `web`。自定义 DSH 数据目录时，先设置 `DSH_HOME`。
2. 完全退出 DSH（包括托盘进程），再重新打开。在 DSH 中配置 A6API provider、模型和模型 API 密钥。
3. 打开设置中的「A6 换商家」，核对版本、启用状态、provider 匹配规则和控制面站点，填写该站点的系统访问令牌和用户 ID 后保存。默认控制面为 `https://a6api.vip`。模型 API 密钥用于模型调用，系统访问令牌用于查询与切换商家。

设置页覆盖值保存在 DSH 数据目录的 `a6-failover/config.json`。点击「清除本地覆盖」可恢复 profile 配置。使用脚本安装后，可从解压目录运行 `node scripts/install.mjs --profile desktop --uninstall` 卸载。本目录是独立插件源码；下载此仓库后，进入 `dsh-a6-failover` 目录执行安装命令。

## 路由策略

| 状态 | 请求行为 |
|---|---|
| 平台默认策略 | 平台选商，插件监测各个请求。从发送到收到首块有效响应计时。 |
| 智能路由（故障接管） | 可恢复的快速故障先按预算原路重试。任一受管请求持续失败，或连续 30 秒没有首块有效响应，就尝试切换到合格商家。 |
| 智能路由（手动） | 点击「开启手动智能路由」，对本次 DSH 运行的所有受管会话生效，持续到点击「恢复平台默认策略」或重启。 |
| 待恢复平台默认 | 自动接管在所有受管请求、重试和切换均空闲后恢复平台路由。上一次运行遗留的插件固定也需要核对并清理。平台确认后才显示已恢复。 |

各会话独立计时。同站点、令牌和模型共用固定商家，并发故障共享切换结果。首块总预算从第一次发送开始计算，默认 180 秒，包含重试、选商、确认固定及新商家响应。收到正文、推理或工具输出后再出错，会保留已输出内容并报告异常，避免重复执行工具。收到有效首块后，连续等待上游 30 秒仍无有效进展时结束该流。自动接管在全部会话空闲一秒后释放；这期间的新请求继续沿用当前商家。启动和手动恢复平台默认时，清除受管令牌下全部模型的固定商家，包括遗留绑定；其他令牌保留。失败时显示正在恢复并后台重试，受影响请求等待确认。手动开启智能路由时不预先绑定，模型收到新请求时才选择并固定商家。

对于明确要求生成文档或文件的简短请求，若回合结束时只有一段准备工作说明且没有工具调用，设置页的最近事件会显示「交付待核对」和核对编号。该提醒供人工复核，DSH 的回合完成状态由宿主维护。

## 智能选商

插件先检查报价、状态和质量门槛。`maxEffectiveRatio` 默认是 `0.7`，即按相同用量假设比较时，商家预计成本最多为官网的 70%。在合格商家中按历史延迟从低到高取较快的一半，再按预计成本、可靠性和延迟加权排序。三项默认权重为 60、30、10。候选延迟 P50 是历史样本的中位数，用于比较候选。单次请求的 30 秒切换阈值使用该请求从实际发送到有效首块的等待时间。

官网缓存命中率估算默认为 95%。商家缓存命中率估算优先使用达到 `cacheMeasureMinSamples` 门槛的本机数据，默认至少 3 次。输出与输入 token 比例优先采用满足 `outputRatioMinSamples` 的样本，默认至少 2 次，否则采用 `outputToInputRatio`，默认 0.03。

## 设置页与人工举报

打开「A6 换商家 → 当前路由策略」可查看本次运行的策略以及各 provider、模型的实际状态。展开一条路由可读到已确认的商家与渠道、每百万输入 token 的预计成本、缓存命中率及其来源、候选延迟 P50。平台自主选商或样本不足时，相应字段可能为空。设置页定期刷新，也可点击「刷新状态」。

插件在本地记录能从响应流验证的格式异常。设置页从最近 512 条日志中保留最多 20 条格式异常供复核。展开记录后可复制本地请求标识、时间、渠道、判定规则与耗时等脱敏字段，自行核对并决定是否向平台举报。请求标识由插件生成；平台排查时可同时提供时间、模型与渠道。任务未完成、回复不合预期和协议格式异常需要分别判断，单条记录不足以认定商家欺诈。

数据目录默认是用户主目录下的 `.dsh`，自定义时使用 `DSH_HOME`。PowerShell 可查看最近 30 条本地事件。

```powershell
$dshDir = if ($env:DSH_HOME) { $env:DSH_HOME } else { Join-Path $env:USERPROFILE '.dsh' }
Get-Content (Join-Path $dshDir 'a6-failover/events.jsonl') -Tail 30
```

`boot` 事件的 `version` 应为 `0.6.2`。在源码目录运行 `node scripts/self-test.mjs` 可执行本地自检。
